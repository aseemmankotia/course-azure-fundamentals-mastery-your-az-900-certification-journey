## Chapter 1: Cloud Computing Foundations: The 'Why' Behind the Cloud — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is cloud computing? | The delivery of computing services (servers, storage, databases, networking, software) over the internet ("the cloud") on a pay-as-you-go basis |
| 2 | What are the three main cloud service models? | IaaS (Infrastructure as a Service), PaaS (Platform as a Service), and SaaS (Software as a Service) |
| 3 | What does IaaS provide and who manages what? | IaaS provides virtualized computing resources; customer manages OS, applications, and data; provider manages physical hardware and virtualization |
| 4 | What does PaaS provide and what is it best for? | PaaS provides a platform for developing and deploying applications; best for developers who want to focus on code without managing underlying infrastructure |
| 5 | What does SaaS provide? Give an example. | SaaS provides complete software applications over the internet; examples include Microsoft 365, Salesforce, and Gmail |
| 6 | What is the difference between Public, Private, and Hybrid cloud? | Public: shared infrastructure owned by provider; Private: dedicated infrastructure for one organization; Hybrid: combination of both |
| 7 | What is the Shared Responsibility Model? | A framework defining security responsibilities split between cloud provider and customer, varying by service model (IaaS/PaaS/SaaS) |
| 8 | In the Shared Responsibility Model, what is the customer ALWAYS responsible for? | Data, endpoints, account/access management, and identity management |
| 9 | What is High Availability in cloud computing? | The ability of a system to remain operational and accessible with minimal downtime, often measured in "nines" (99.9%, 99.99%) |
| 10 | What is the difference between Scalability and Elasticity? | Scalability: ability to handle increased load by adding resources; Elasticity: ability to automatically scale resources up AND down based on demand |
| 11 | What is Fault Tolerance? | The ability of a system to continue operating properly when one or more components fail |
| 12 | What is CapEx and how does it relate to traditional IT? | Capital Expenditure: upfront spending on physical infrastructure; traditional IT requires large CapEx investments for servers and data centers |
| 13 | What is OpEx and how does cloud computing use it? | Operational Expenditure: ongoing costs for services; cloud uses OpEx through pay-as-you-go consumption-based pricing |
| 14 | What is Agility in cloud computing context? | The ability to rapidly deploy and configure cloud resources as business requirements change |
| 15 | What is the consumption-based pricing model? | A model where you only pay for the resources you actually use, rather than paying for capacity you might not need |

### Key Terms

| Term | Definition |
|------|-----------|
| IaaS | Infrastructure as a Service - rent IT infrastructure (VMs, storage, networks) from a cloud provider |
| PaaS | Platform as a Service - provides environment for building, testing, and deploying software applications |
| SaaS | Software as a Service - complete software solutions delivered over the internet |
| Elasticity | Automatic scaling of resources to match current demand, both up and down |
| Shared Responsibility Model | Security framework dividing accountability between cloud provider and customer |
| CapEx | Capital Expenditure - upfront costs for physical infrastructure |
| OpEx | Operational Expenditure - ongoing costs for services and consumption |
| Disaster Recovery | Strategies and services to recover data and resume operations after a catastrophic event |

### Memory Tricks
- **"Pizza as a Service"**: IaaS = you buy ingredients (make everything); PaaS = you buy dough & toppings (cook at home); SaaS = you order delivery (just eat)
- **"SAFE" for cloud benefits**: Scalability, Availability, Fault tolerance, Elasticity
- **"CapEx = Capture it, OpEx = Operate it"**: CapEx captures/owns assets upfront; OpEx operates/rents services ongoing
- **"The higher the 'aaS', the less you manage"**: IaaS (manage most) → PaaS (manage some) → SaaS (manage least)
